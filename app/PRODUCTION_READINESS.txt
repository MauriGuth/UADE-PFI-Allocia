ALLOCIA — PREPARACIÓN PARA PRODUCCIÓN
Última revisión técnica: 9 de octubre de 2026

ARQUITECTURA OPERATIVA
1. Ejecutar una instancia API y PostgreSQL/Redis administrados con TLS.
2. Ejecutar `pnpm --filter api migrate:production` como release command antes
   de iniciar una versión nueva. Nunca activar synchronize en producción.
3. Ejecutar `pnpm --filter api worker` como proceso separado y permanente.
   El worker consulta cada 30 segundos, pero crea un solo trabajo por mercado,
   fecha y fase gracias a una clave única y un advisory lock de PostgreSQL.
4. Mantener el calendario por bolsa con zona horaria, feriados y cierres
   anticipados. El worker se bloquea cuando el calendario vence. Cripto se
   analiza a las 00:00 y 12:00 UTC.
5. Ejecutar la API y el worker con las mismas variables de entorno y archivos
   de cobertura. Probar backups cifrados y una restauración antes del alta.

DATOS E IA
- Las cantidades se cifran con AES-256-GCM y una clave exclusiva del backend.
  Rotar la clave exige una migración planificada; conservarla en el gestor de
  secretos y en el procedimiento de recuperación, nunca en Git.
- El modelo Anthropic recibe sólo el snapshot público del activo y las noticias.
  No recibe identidad, email, cantidades ni composición del usuario.
- El esquema de salida exige fuentes conocidas. Las citas deben coincidir de
  forma literal con el material recuperado. Ante fuente ausente, vieja, URL
  insegura, modelo sin configurar o validación fallida, el resultado queda como
  “datos insuficientes” y no crea escenarios ni alertas.
- El “mega prompt” se adaptó a un prompt de sistema controlado. Se descartaron
  puntajes, probabilidades y señales técnicas imposibles de respaldar con los
  datos actuales. La app no opera ni dispara transacciones.

COBERTURA GLOBAL
“Global” significa una lista explícita de activos y sesiones habilitadas por el
operador. No equivale a todas las empresas del mundo. Cada región debe tener un
proveedor autorizado, símbolos probados, divisa correcta, calendario vigente y
licencia que permita mostrar y almacenar los datos. El ejemplo incluido cubre
EE.UU., ADR argentinos y cripto; debe ampliarse antes de prometer otras bolsas.

NOTIFICACIONES
- Las alertas son opt-in y sólo se crean para usuarios que poseen el ticker.
- La pantalla bloqueada muestra un aviso genérico, sin activo ni cantidad.
- El outbox deduplica por alerta/dispositivo, limita reintentos y consulta
  receipts. Un POST de resultado ambiguo no se reenvía para evitar duplicados.
- PUSH_ENABLED debe permanecer false hasta configurar APNs, FCM, un token de
  Expo y probar alta, entrega, baja, expiración y DeviceNotRegistered en equipos
  físicos iOS/Android. Expo Go no valida push remoto de Android.

SEGURIDAD APLICADA
- Cookie web HttpOnly, SameSite Strict, CSRF por Origin, sesiones revocables,
  JWT de 12 horas con issuer/audience, contraseñas bcrypt coste 12 y mínimo 12.
- CORS explícito, CSP en web, Helmet, body de 32 KB, DTO estrictos, rate limit
  compartido en Redis, errores 5xx genéricos y request IDs sin datos sensibles.
- FK por propietario, consultas con userId, borrado en cascada, límite de 500
  posiciones, escritura concurrente serializada y cantidades de hasta 8 decimales.
- El usuario puede desactivar alertas, exportar sus datos y eliminar la cuenta,
  posiciones, alertas y dispositivos.
